# 实测结果（2026-10-14）

源模型：上游 `BRNNPNSN` v3，SHA256 与 `models/pnsn-{fp32,int8}.json` 一致。以下是实际运行数据，不是估算。

## 固定窗口端到端概率推理

包含去均值/归一化及 GPU 输入输出同步，不含 NMS、模型加载；50 次暖态运行中位数，CPU 1 线程。数据为上游 100 Hz E/N/Z SAC 波形的前 6144/10240 点。6144 段没有超过默认阈值的震相，10240 段为 2 个。

| 主机 / 后端 | 精度 | 6144（ms） | 10240（ms） |
|---|---|---:|---:|
| M4 Max / torch-cpu | fp32 | 3.270 | 5.154 |
| M4 Max / c-cpu | fp32 | 3.997 | 6.674 |
| M4 Max / c-cpu | int8 | 2.983 | 4.859 |
| M4 Max / mlx | fp32 | 1.054 | 1.388 |
| M4 Max / mlx | int8 | 1.127 | 1.520 |
| RTX 5090 / 远程 x86 / torch-cpu | fp32 | 4.876 | 7.061 |
| RTX 5090 / 远程 x86 / torch-cuda | fp32 | 3.216 | 3.479 |
| RTX 5090 / 远程 x86 / c-cpu | fp32 | 14.193 | 23.789 |
| RTX 5090 / 远程 x86 / c-cpu | int8 | 7.694 | 12.820 |
| RTX 5090 / 远程 x86 / c-cuda | fp32 | 3.735 | 5.665 |
| RTX 5090 / 远程 x86 / c-cuda | int8 | 1.896 | 2.238 |

MLX FP32 在本次 M4 Max 上比 PyTorch CPU 快约 3.7 倍，INT8 没有进一步明显加速，应优先按准确率/内存需求选型。C INT8 在本机比自己的 FP32 快约 1.37 倍，比 PyTorch CPU 单窗略快；远程 x86 C 核心仍慢于 PyTorch 的成熟 CPU 算子。CUDA INT8 比自写 CUDA FP32 快约 2.53 倍，比同机 PyTorch CUDA 单窗快约 1.55 倍。不能概括为“改成 C 一定更快”。

各后端完整冷启动、p95、概率误差与拾取匹配记录：[本机](local-benchmark.json)、[远程](remote-benchmark.json)。MLX 首次编译可能明显更慢，编译缓存状态影响冷启动时间。

## 任意长度：包含堆后处理

260010 点为上游 26001 点实际波形重复 10 次，仅用于性能压力测试，不是 10 个独立真实事件。暖态 5 次中位数：

| 后端 | 26001 点（ms） | 260010 点（ms） |
|---|---:|---:|
| c-cpu-fp32 | 20.640 | 196.248 |
| mlx-fp32 | 4.732 | 45.754 |
| c-cpu-int8 | 14.874 | 143.445 |
| mlx-int8 | 5.006 | 48.284 |
| upstream-jit-cpu | 13.217 | 471.920 |

260010 点上，C INT8 完整拾取比旧 TorchScript CPU 快约 3.29 倍，MLX FP32 快约 10.31 倍。输出数量均为 31，但本版本修复了 float32 均值和旧 JIT 尾窗索引行为，不能把这次计时当作逐点严格等价测试。完整记录：[任意长度基准](local-trace-benchmark.json)。

## 人工标签准确率：5730 窗口、31 省

复用现有只读测试缓存，2020–2022 测试数据、10240 点、variant 0；依据 `test.json` 的有效行数排除补零缓存槽。逐通道重新归一化对所有模型一致；PyTorch CUDA 参考关闭 TF32。阈值 0.1，NMS gap 300，人工标签匹配容差 50 点（100 Hz 下 0.5 秒）。无训练、无为量化重新选择阈值。

| 模型 | TP | FP | FN | Precision | Recall | Pg/Sg micro F1 |
|---|---:|---:|---:|---:|---:|---:|
| torch-fp32 | 9733 | 1547 | 1563 | 86.2855% | 86.1632% | 86.2243% |
| native-fp32 | 9733 | 1547 | 1563 | 86.2855% | 86.1632% | 86.2243% |
| native-int8 | 9727 | 1546 | 1569 | 86.2858% | 86.1101% | 86.1979% |

INT8 F1 变化为 **-0.0264 个百分点**；少 6 个 TP，少 1 个 FP。FP32 原生版与参考的 TP/FP/FN 完全相同。

同时对 Pg/Sg/Pn/Sn 四类预测做配对：参考 11838 个，INT8 11822 个，在 50 点内匹配 11755 个（99.2989%）；参考未匹配 83 个，INT8 新增未匹配 67 个。匹配到时误差中位数 0 点、p95 2 点。最大概率误差 0.133783，平均 0.00005238；这说明 INT8 并非概率无损。

FP32 最大概率误差 0.00000989，四类拾取 100% 在容差内配对；平坦峰顶会受舍入影响，最大到时差 8 点，p95 0 点。

人工标签评估仅覆盖 Pg/Sg。四类配对是与 FP32 预测的一致性，不是 Pn/Sn 的人工准确率，也不是跨设备/跨区域泛化保证。此批标签分数来自 CUDA W8A8；MLX W8A32 通过本机合成、真实波形和重复调用数值测试，尚未对这 5730 条在 MLX 上做完整人工标签评分。

完整省级与分震相结果：[labeled-evaluation.json](labeled-evaluation.json)。

## 模型与边缘内存

| 项目 | FP32 | INT8 |
|---|---:|---:|
| 模型文件 | 1,814,772 B | 477,012 B |
| 10240 点 CPU 模型 + 工作区 + 转置权重打包 | 3,495,512 B | 1,847,096 B |

INT8 模型文件缩小 73.71%（约 3.80 倍）。CPU context 字节数由 `pnsn_memory_bytes` 计算，INT8 约 1.76 MiB，不是进程 RSS。调用方波形/输出、NMS 临时内存、分配器、MLX/CUDA 不包括在内。NMS 预算 32768 个候选时，候选及 NMS 的额外峰值上界约 2.75 MiB，因此不能把整个系统说成只用 477 KB。

- macOS ARM64：共享库、静态库、安装、CLI，NEON/DOTPROD 数值，MLX FP32/Q8，真实波形长序列。
- Linux x86_64：C CPU AVX2、CUDA 12.8 / RTX 5090，真实波形 CLI，固定长度与长序列回归。
- 100 组随机候选与独立贪心 NMS 对比，覆盖重复时间、同分、跨震相和边界距离。
- float64 大直流偏置、int32 极值、恒定通道、NaN/Inf、0/1/2 点波形、128/6144/10240 窗口及尾窗、raw+diff，模型损坏和预算错误。
- AddressSanitizer/UndefinedBehaviorSanitizer：单元测试和完整真实波形 C CLI 通过。
- Windows/macOS/Linux CI 配置已提供；Windows CI 和实体 ARM 边缘板没有在本次会话运行。
